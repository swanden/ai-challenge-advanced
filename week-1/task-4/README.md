рабочая конфигурация. Главный вывод оказался не тем, что ожидался.

## 2. Контекст: лекция и чат курса

### Лекция

Отдельной лекции под День 4 нет. Вводная лекция потока общая: она разбирает стек абстракций
код-агента — главный агент как оркестратор, субагенты, скиллы, команды, MCP — и к локальным
моделям прямого отношения не имеет. Поэтому методику дня задают текст задания и практика
однокурсников.

Одна мысль лекции здесь всё же сработала, хотя и от обратного. Лекция строит картину, в которой
агент сам планирует, сам вызывает инструменты и сам проверяет результат. Именно эта способность
и оказалась тем, что локальные модели не воспроизвели — то есть день проверяет на прочность
центральное допущение всего потока.

### Чат курса

К моменту прогона в чате уже обсуждали ровно то, во что мы упёрлись, и это стоит привести, потому
что совпадение почти дословное.

Олег Ионов спрашивал, удалось ли кому-нибудь получить адекватный результат с локальной моделью, и
описывал, что у него на двух задачах провалилось: агент либо просто рассуждал, как он сделает,
либо начинал делать полный бред. Пробовал Qwen3-4b с 16k контекста. Отдельно он же отметил, что
в качестве чата модель работает более-менее хорошо, а вот проблема была подобрать модель с
tool-calling, чтобы можно было запустить в агентном режиме.

Это буквально наш результат: чат работает, агентный режим — нет, и упирается всё в вызов
инструментов.

Виктор Добров подошёл иначе — запустил ресёрч между моделями и получил подбор: `qwen 1.5b` для
автокомплита, слабовато, но вышло, большие вещи не тянет; `qwen 30b` для чата, определяет, за что
отвечает вьюмодель и какую логику выполняет, но насчёт составления толкового запроса он
сомневался. Наше разделение ролей (1.5b на автокомплит, 7b на чат) совпало с этим независимо.

Андрей Шерстнев пробовал русскоязычную `vikhr 12b q4` — код она дала, но не совсем правильный.
Тоже знакомый исход: генерация есть, качество не дотягивает.

Отдельный сквозной мотив недели, влияющий на выбор конфигурации: после Дня 1 участники стали
упираться в лимиты, потому что файл правил с примерами кода добавляет тысячи токенов к каждому
запросу. Для локальной модели это критичнее, чем для облака — контекст там дефицитный ресурс, и
правила приходится либо резать, либо мириться с тем, что они съедают треть окна.

## 3. Отклонение от условия: Continue больше нет

Задание называет Continue.dev, но его **нет в маркетплейсе JetBrains**. В июне 2026 Continue
купил Cursor; в README репозитория `continuedev/continue` написано, что он больше не
поддерживается активно и переведён в режим только для чтения, версия 2.0.0 объявлена финальной.
Поиск по маркетплейсу его не находит — установка возможна только вручную из jar.

Замена — **ProxyAI** (бывший CodeGPT, плагин JetBrains 21056): автодетект Ollama, раздельные роли
для чата и автокомплита. Тот же выбор и по той же причине сделал ещё один участник курса.

Рассматривался штатный **JetBrains AI Assistant**: он подключает Ollama из коробки, а на тарифе
AI Free локальные модели доступны без ограничений. Но в его настройках под блоком локальных
моделей прямо написано, что на автокомплит они не влияют — тот работает только на облачной модели
JetBrains. Половина требования задания не закрывается, поэтому вариант отпал.

## 4. Конфигурация

**Железо:** MacBook M3 Max, 48 ГБ объединённой памяти. **Ollama:** 0.30.11.

Потолок памяти сразу отсёк часть вариантов: `qwen3-coder-next` весит 51 ГБ и на 48 ГБ физически
не помещается — закачка прервана на 9%. Это первое практическое ограничение локального пути:
топовые открытые модели упираются не в деньги, а в железо.

| Роль | Модель | Почему |
|---|---|---|
| Автокомплит, Next edits | `qwen2.5-coder:1.5b` | срабатывает на каждое нажатие клавиши, решает скорость |
| Chat, Agent, Inline edit, прочее | `qwen2.5-coder:7b` | качество важнее задержки |
| Агентные прогоны | `devstral` (24B, ~14 ГБ) | обучена Mistral совместно с All Hands AI специально под агентную работу |

Модель общего назначения `qwen2.5:7b` с прошлого курса для автокомплита не годится — не обучена
на FIM. ProxyAI при подключении предлагал переставить все роли на `nomic-embed-text` (модель
эмбеддингов, генерировать текст не умеет вовсе) — предложение отклонено.

**Параметры:** temperature 0.1–0.2, top_p по умолчанию. **FIM-шаблон:** `CodeQwen2.5`, определён
ProxyAI автоматически. **Телеметрия** ProxyAI отключена вручную — иначе смысл локального запуска
теряется наполовину.

**Правила проекта:** `CLAUDE.md` песочницы `tasks-api` — стек, слои, обязательные паттерны,
антипаттерны, шаблон метода. В ProxyAI подаётся через `@CLAUDE.md`, в Claude Code и Aider
читается автоматически.

**Подопытный проект:** `tasks-api` — учебный HTTP-сервис задач на Go: стандартная библиотека,
`http.ServeMux`, слои `cmd` / `internal/task` / `internal/httpapi`, in-memory хранилище.

## 5. Из чего состоит связка

Четыре инструмента, и роли у них разные — путаница между ними и была источникомполовины
неверных выводов по ходу дня.

**Ollama** — движок инференса. Скачивает модели, держит их в памяти и отдаёт по HTTP на
`localhost:11434`. Сам по себе он ничего не решает: это просто способ запустить модель локально
и обратиться к ней запросом. Важная деталь, всплывшая по ходу: с января 2026 Ollama умеет не
только свой формат, но и Anthropic-совместимый эндпоинт Messages — благодаря чему на неё можно
направить Claude Code двумя переменными окружения.

**ProxyAI** — плагин JetBrains (бывший CodeGPT, id 21056). Отвечает за то, что видно в IDE:
серые подсказки автокомплита, панель чата, применение предложенных правок. Модели назначаются
по ролям — отдельно на автокомплит, отдельно на чат и агента. Контекст проекта сам не собирает:
файлы подаются вручную через `@`.

**Claude Code** — тот самый харнесс, на котором сделаны Дни 1–3. Здесь он понадобился как
контрольный: если направить его на локальную модель, всё остальное остаётся неизменным — тот же
механизм правки файлов через точное совпадение строк, то же чтение `CLAUDE.md`, те же субагенты.
Меняется ровно одна переменная — модель. Это позволило отделить вину плагина от вины модели.

**Aider** — терминальный агент. Ключевое отличие от всех остальных: он **не использует протокол
вызова инструментов**. Модель отвечает обычным текстом в формате диффа, Aider сам его парсит и
применяет к файлам. Именно поэтому он оказался единственным, что доехало до применённого кода —
ему нечему было не совпасть с моделью.

Схема ролей: Ollama держит модель, ProxyAI и Aider — два разных способа доставить её работу в
проект, Claude Code — контрольный замер на неизменном каркасе.

## 6. Что проверялось

Один и тот же промпт агентной задачи прогонялся через пять разных связок:

> Добавь поиск задач: `GET /tasks?q=подстрока` — фильтрует по названию, регистронезависимо.
> Пройди по всем слоям, соблюдай конвенции из `CLAUDE.md`.

### 6.1. Автокомплит — работает

Серые подсказки появляются при наборе, модель дописывает сигнатуры и тела методов в стиле
проекта. Первый вызов после старта медленный — модель грузится в память. Это лучший сценарий
для локальной модели: узкая задача, мгновенный отклик, нулевая стоимость.

### 6.2. Чат — работает, но контекст подаёшь ты

Вопрос «Что делает `Store.Create`?» без указания файла — модель ответила, что функция «создаёт
новый экземпляр хранилища». Неверно: `Create` создаёт задачу, обрезает пробелы, возвращает
`ErrEmptyTitle`; хранилище создаёт `NewStore`.

Проверка повторена после перезапуска IDE со сбросом кэшей и полной переиндексации, с открытым
`task.go` в редакторе — ответ изменился, но суть та же: модель честно сказала, что «в
предоставленной информации не указано, что делает функция».

С явным контекстом (`@task.go`) — ответ полностью правильный, по шагам: `strings.TrimSpace`,
проверка на пустоту, захват мьютекса, создание `Task` с id из `nextID`, инкремент, освобождение.

Вывод: дело не в модели, а в плагине. **ProxyAI не собирает контекст проекта сам.** Claude Code
в тех же условиях ходит по файлам инструментами `Read`, `Glob`, `Grep`.

### 6.3. ProxyAI Chat + генерация фичи — код хороший, применение ломает файлы

Генерация заняла ~30 секунд и была качественной: план из трёх шагов, `Store.Delete` с мьютексом
и проверкой ключа, хендлер с `strconv.Atoi` и 400 на нечисловой id, `errors.Is` → 404,
регистрация маршрута. Стиль проекта выдержан.

Развалилось на применении. Первая попытка: предпросмотр показывал вставку тела `Delete` внутрь
функции `List`, применение зависло, в файлах ноль изменений. Вторая (выяснилось, что после
`Apply` нужен ещё `Accept All` по каждому блоку) — правки легли, но файл сломан:

```
handler.go:58:1: syntax error: non-declaration statement outside function body
handler.go:128:1, 158:2, 165:2: syntax error
```

В файле оказались: буквальные разделители патча `=======` на строках 58 и 128, функция `delete`
определена дважды, осиротевшая копия тела `patch` вне функции.

Отдельно — **тихая регрессия**. Модель заодно переписала `List`, о котором не просили:

```go
// было
for id := 1; id < s.nextID; id++
// стало
for id := range s.tasks
```

Комментарий над функцией по-прежнему обещает «отсортированные по id для детерминированной
выдачи», а обход map в Go намеренно случаен. Порядок сломан, код выглядит правдоподобно.

### 6.4. ProxyAI Agent — отказ обоих звеньев

**Модель не поняла архитектуру:** сгенерировала бойлерплейт на чужом стеке — импорты
`github.com/gin-gonic/gin`, `github.com/your-repo/handlers`, `github.com/your-repo/routers`
(последние два не существуют вовсе). Проект на стандартной библиотеке, `CLAUDE.md` прямо
запрещает внешние зависимости и сторонние роутеры.

**Плагин применил всё в один файл:** восемь блоков, адресованных разным файлам, легли в
`handler.go`. Туда же попали два последних пункта плана, которые были **командами проверки для
терминала**, а не кодом — в середине файла оказались `func main()`, `exec.Command("bash",
"./scripts/build.sh")` и голая строка `go run main.go`. Создавать новые файлы плагин не умеет.

Применение заняло около десяти минут, `Apply` приходилось жать по несколько раз.

### 6.5. Claude Code + qwen2.5-coder:7b — вызов инструмента текстом

Чтобы отделить вину плагина от вины модели, тот же промпт прогнан через Claude Code,
направленный на Ollama. Ollama с января 2026 поддерживает Anthropic-совместимый эндпоинт
Messages, поэтому переключение — две переменные окружения. Условия идентичны Дням 1–3: тот же
харнесс, тот же механизм правки файлов через точное совпадение строк, тот же `CLAUDE.md`.

Через 52 секунды модель выдала текстом выдуманный вызов инструмента:

```
{"name": "TaskCreate", "arguments": {"subject": "Add search functionality...", ...}}
```

Инструмента `TaskCreate` не существует — у Claude Code это `Read`, `Edit`, `Write`, `Bash`,
`Glob`, `Grep`. Модель не вызвала инструмент, а сымитировала вызов. Файлы не тронуты.

### 6.6. Claude Code + devstral — остановилась на плане

Та же связка, но с моделью, обученной под агентную работу. Результат заметно лучше: связный план,
попадание в реальную структуру проекта (`internal/httpapi`, `cmd/tasks-api/main.go`). Но
закончила вопросом «Would you like me to continue with implementing these steps?» — описала
работу вместо того, чтобы её сделать. 4 минуты 40 секунд, файлы не тронуты.

Промахи в самом коде тоже были: `r.HandleFunc("/tasks", h.listTasks).Methods("GET")` — синтаксис
gorilla/mux, а проект на `http.ServeMux`; `http.Error(...)` вместо `writeError` — прямой
антипаттерн из `CLAUDE.md`; выдуманные методы `FilterByTitle` и `ListAll`.

### 6.7. Aider + devstral — единственный успех

Aider не использует протокол вызова инструментов вообще: модель отвечает обычным текстом в
формате диффа, а Aider сам его парсит и применяет.

**Правки применились чисто.** Оба файла целые: ни маркеров, ни дублей, ни осиротевшего кода.
`go build` и `go vet` прошли — впервые за все прогоны дня.

**Доменный код безупречен.** Метод `Search` в `task.go` написан ровно по конвенциям проекта:
`RLock` с `defer`, `strings.ToLower` с обеих сторон, обход по возрастанию id как в соседнем
`List`, `ctx` первым аргументом. Придраться не к чему.

**Но сервис падает при старте:**

```
panic: parsing "GET /tasks?q={query}": at offset 5: bad wildcard segment (must start with '{')
```

Модель попыталась зарегистрировать query-параметр как часть маршрута — `http.ServeMux` так не
умеет, он матчит только путь. Фильтр следовало читать из `r.URL.Query().Get("q")` внутри
существующего хендлера `list`, отдельный маршрут не нужен вовсе. Отсюда же второй промах:
`r.PathValue("query")` вернёт пустую строку.

Показательно, что **компилятор это не ловит**: строка маршрута синтаксически валидна, ошибка
вылезает только в рантайме при регистрации. Без запуска дефект ушёл бы в коммит.

## 8. Главный вывод: барьер — в совпадении модели и каркаса

К этому выводу пришли не сразу — через две отброшенные гипотезы, и путь стоит описать, потому
что каждая казалась очевидной.

**Гипотеза первая: модель слабая.** Естественное объяснение первых отказов —
`qwen2.5-coder:7b` мала для агентной работы. Опровергается двумя фактами. Во-первых, доменный
код, который модели генерировали, был хорош: `Store.Delete` от `qwen2.5-coder` и особенно
`Search` от Devstral написаны по конвенциям проекта без единого замечания. Во-вторых, замена на
Devstral — модель втрое крупнее, обученную специально под агентную работу — результат не
починила: та тоже не тронула ни одного файла.

**Гипотеза вторая: модель не умеет вызывать инструменты.** Логичное продолжение: если модель
печатает вызов текстом, значит, протокол ей неизвестен. Проверяется одной командой — и тоже
опровергается:

```
$ ollama show devstral | grep -A6 Capabilities
  Capabilities
    completion
    tools
```

`tools` заявлены **у обеих** моделей. Ollama формально идёт нативным путём, а поведение всё равно
ломается.

Это ровно то, что независимо зафиксировал другой участник курса: заявленная в `ollama show`
поддержка `tools` отражает **шаблон**, а не поведение модели — проверять надо прогоном, а не
флагом.

**Что оказалось на самом деле.** Ответ нашёлся в том же выводе `ollama show`, строкой ниже — в
системном промпте, зашитом в саму модель:

```
You are Devstral, a helpful agentic model trained by Mistral AI
and using the OpenHands scaffold.
```

**Модель на уровне обучения ждёт конкретный каркас — OpenHands.** Мы запускали её в Claude Code
и Aider. Отсюда её поведение: она не сломалась, она отработала как привыкла — составила план и
спросила подтверждения, потому что в OpenHands цикл устроен через подтверждения.

Отсюда же понятно, почему поиск «более удобного плагина» бесперспективен. Проблема не в плагинах
и не в выборе IDE, а в несовпадении форматов, и оно образует замкнутый круг:

- модель отдаёт JSON → **Cline** ждёт XML-теги в стиле Anthropic → зацикливание (открытый баг,
  заведён на VS Code-версию, то есть смена IDE не лечит);
- модель отдаёт XML → **Continue** ждёт нативный `tool_calls` → вызовы игнорируются;
- **ProxyAI** формат принимает, но не умеет накладывать патч и создавать файлы;
- **Aider** не требует протокола вообще — поэтому единственный поехал.

## 9. Рабочая конфигурация

Всё внутри GoLand, надёжного плагина под локальный агент в боковой панели сейчас не существует:

| Задача | Инструмент | Где |
|---|---|---|
| Автокомплит | ProxyAI + `qwen2.5-coder:1.5b` | боковая панель |
| Чат по коду | ProxyAI + `qwen2.5-coder:7b`, контекст через `@` | боковая панель |
| Агентная правка | Aider + `devstral` | вкладка Terminal |

Aider правит файлы на диске, GoLand подхватывает изменения мгновенно — видно в дифф-маркерах и
в панели Commit. То есть агент живёт в терминале, а не в панели, но остаётся внутри IDE.

## 10. Облако против локальной модели

| Критерий | Облако (Claude Code, Opus 5) | Локально (лучшая связка: Aider + devstral) |
|---|---|---|
| Автокомплит | нет такой функции | работает, подсказки в стиле проекта |
| Чат по коду | сам находит файлы | понимает при явно поданном контексте |
| Понимание контекста | обходит репозиторий сам | контекст собирает человек |
| Качество доменного кода | эталон | **сопоставимо** — `Search` написан безупречно |
| Знание специфики фреймворка | точное | промах: не знает, что `ServeMux` не роутит по query |
| Применение правок | точное совпадение строк, за 4 дня ни одной ошибки | чисто у Aider, ломает файлы у ProxyAI |
| Агентный цикл | работает: субагенты, ворота, проверки | только при совпадении модели с каркасом |
| Скорость генерации | сопоставима | 30 с чат, 52 с и 4 мин 40 с агентные прогоны |
| Скорость применения | мгновенно | ~10 минут через ProxyAI, мгновенно через Aider |
| Тихие регрессии | не наблюдались | переписала `List`, сломав порядок выдачи |
| Потолок по железу | не касается | 48 ГБ отсекают модели крупнее ~30 ГБ |
| Работа без интернета | невозможна | полная |
| Стоимость | лимиты подписки | ноль |
| Приватность | код уходит на сервер | код не покидает машину |

## 11. Для чего хватает локальной модели

**Хватает** на автокомплит — лучший её сценарий: короткие фрагменты, мгновенный отклик, и мелкая
модель на 1.5B справляется. Хватает на объяснение написанного кода при явно поданном файле:
разбор `Store.Create` был точным по шагам. Хватает на генерацию отдельного метода — доменный
`Search` оказался не хуже облачного. И хватает на работу без интернета: в поезде, в самолёте,
в закрытом контуре.

**Не хватает** на знание специфики фреймворка: обе модели уверенно писали то, чего в
`http.ServeMux` нет. Не хватает на самостоятельный обход кодовой базы — контекст собираешь
руками. Не хватает на удержание архитектуры целиком: в агентном промпте модель вышла за рамки
задачи и притащила чужой стек, хотя правила лежали рядом. И на неё нельзя положиться без ревью
каждой строки — тихая порча `List` и паника на старте прошли бы незамеченными.

**Облако незаменимо** там, где нужен многошаговый автономный цикл с проверкой результата — то,
что делали Дни 2 и 3: профили, субагенты с урезанными инструментами, ворота между этапами,
прогон тестов и браузерных сценариев. Ни один шаг этой конструкции локальная связка не
воспроизвела.

## 12. Что получилось у других участников

Результат не единичный — успеха в агентном режиме не добился никто из тех, чьи отчёты доступны.

**Sergio-rsd (captain-blood, Kotlin).** Прошёл почти тот же путь: тоже обнаружил, что Continue
выпал из маркетплейса, тоже заменил его на ProxyAI, тоже разделил роли — мелкая модель на
автокомплит, крупная на чат. Проверял три модели: `qwen2.5-coder:14b`, `deepseek-coder-v2:16b`,
`codellama:13b-instruct`.

Его итог: **0 из 6 прогонов** (три модели × две задачи) не дали кода без хотя бы одной ошибки
компиляции — каждая модель минимум раз выдумала несуществующий метод или константу. Настоящий
агентный режим — **0 из 3 моделей** дали хоть один рабочий прогон, причём две из трёх вообще не
имеют `tools` в Capabilities, и ProxyAI на них честно падает с `400 does not support tools`.

Совпадение с нашим прогоном дословное: в Agent-режиме его модель писала сырой JSON вызова текстом
вместо вызова — сначала фейковый `TodoWrite`, потом фейковый `exit`. У нас это был выдуманный
`TaskCreate`.

И он сделал проверку, которую стоит отметить отдельно: прогнал модель **напрямую через Ollama API
с параметром `tools`, минуя плагин целиком** — она снова вернула вызов текстом в поле `content`
вместо `tool_calls`. Значит, дело в модели и её шаблоне, а не в интеграции плагина. Это прямо
подтверждает наш вывод из раздела 8.

Две его находки объясняют часть наших трудностей. Первая: ProxyAI **не даёт настроить `num_ctx`
в UI вообще** — из-за этого файл на 1719 строк вместе с правилами не влезал в контекст, и он ушёл
на прямые вызовы Ollama API скриптом. Вторая: у него весь `Main.kt` плюс `CLAUDE.md` не уложились
даже при `num_ctx=65536` за 600 секунд на 16 ГБ VRAM — пришлось вручную резать контекст до
релевантного сниппета в ~100 строк вместо файла целиком.

Для честности он прогнал ту же задачу на облаке: с первого раза, 5 минут 58 секунд, ни одного
выдуманного метода, тесты 13/13. Контраст с 3/3 локальными моделями, каждая из которых
галлюцинировала минимум одну деталь.

**dpmn (fridge-chef, Go).** Работал не через IDE-плагин, а через терминальный агент opencode.
Его формулировка вывода наиболее точная: **барьер оказался не в железе, а в способности модели
исполнять протокол инструментов**. Из семи моделей на машине агентный цикл тянет ровно одна.

Цифры: запись в репозиторий — **ноль из трёх** попыток, каждый раз по новой причине (описание
вместо работы за 22 минуты → файл-заглушка из трёх байт за 39 минут → запись мимо репозитория в
несуществующий путь за 43 минуты). Агентный bug-fix — **ноль вызовов инструментов за 15 минут**:
модель не открыла код вообще, а пересказала правила из системного промпта и выдала это за
диагноз. Единственный успех — read-only вопрос про эндпоинты, ответ верный, но 15 минут 53
секунды, из них ~14 минут рассуждений перед одним `grep`.

Три разных режима отказа на одном каркасе: `qwen2.5-coder:7b` печатает JSON в текст;
`GigaChat3-10B` шлёт битые вызовы, от которых харнесс крашится; `Qwen3-Coder-Next` задаёт
уточняющие вопросы вместо работы, а с запретом на вопросы — зависает. Последнее — буквально наш
случай с Devstral, которая закончила вопросом «продолжить?».

Его переносимая формулировка, которую мы подтвердили независимо: **заявленная в `ollama show`
capability `tools` отражает шаблон, а не поведение модели** — проверять надо прогоном, а не
флагом. Плюс отдельное предупреждение: автономный режим без изоляции опасен — его модель выдумала
абсолютный путь, и агент создал дерево каталогов вне репозитория и записал туда.

**Чат курса.** Олег Ионов: на двух задачах провалилось, агент либо рассуждал, как он сделает,
либо делал полный бред; отдельно — проблема подобрать модель с рабочим tool-calling для агентного
режима, при том что в качестве чата всё более-менее. Виктор Добров подобрал модели ресёрчем:

русскоязычная `vikhr 12b q4` дала код, но не совсем правильный.

получил рабочий агентный прогон на локальной модели. При этом автокомплит и чат работают у всех,
кто их проверял. Расхождение ровно по той границе, которую описывает раздел 8.

не умеет создавать файлы. Именно поэтому решающими считаются замеры 6.5–6.7, где каркас был
заведомо исправен.

    ├── README.md                        индекс: какой файл к какому разделу отчёта относится
    ├── ollama-capabilities.txt          раздел 8 — вывод `ollama show` по обеим моделям
    ├── proxyai-broken-handler.go.txt    разделы 6.3–6.4 — файл после применения правок ProxyAI

    ├── aider-session.md                 раздел 6.7 — полный лог сессии Aider
    ├── aider-result-task.go.txt         доменный слой после Aider
    ├── aider-result-handler.go.txt      транспортный слой после Aider

Проект лежит в исходном состоянии, с которого начинался каждый прогон, — он собирается и проходит
`go vet`. Результаты прогонов в него **не смёржены**: ни один не дал работающего кода, поэтому они
вынесены в `evidence/` как артефакты, а не как состояние проекта.

Ключевые файлы для проверяющего: `ollama-capabilities.txt` показывает, что `tools` заявлены у
обеих моделей и что Devstral прямо называет свой каркас; `proxyai-build-failure.txt` — во что
превращается файл после применения правок плагином; `aider-runtime-panic.txt` — единственный
прогон, дошедший до компилирующегося кода, и то, чем он закончился при запуске.

Прогоны 6.5 и 6.6 (Claude Code на локальной модели) файловых артефактов не оставили: в обоих
случаях модель не тронула ни одного файла, результат приведён в отчёте цитатой.

## 15. Как воспроизвести

```bash
# движок и модели
ollama serve &
ollama pull qwen2.5-coder:1.5b
ollama pull qwen2.5-coder:7b
ollama pull devstral

# проверка поддержки инструментов (наличие tools не гарантирует поведение)
ollama show devstral | grep -A6 Capabilities

# плагин: GoLand → Settings → Plugins → Marketplace → ProxyAI
# Settings → Tools → ProxyAI → Providers → Ollama:
#   base host http://localhost:11434, Enable code completions, FIM template CodeQwen2.5
# Settings → Tools → ProxyAI → Models:
#   Chat/Agent/Inline edit → qwen2.5-coder:7b, Autocomplete → qwen2.5-coder:1.5b

# агентная правка — в терминале GoLand
export OLLAMA_API_BASE=http://localhost:11434
aider --model ollama/devstral --no-auto-commits

# альтернатива: тот же харнесс, что в Днях 1-3, на локальной модели
export ANTHROPIC_BASE_URL=http://localhost:11434
export ANTHROPIC_AUTH_TOKEN=ollama
claude --model devstral
```

Автономный прогон пула задач. `$ARGUMENTS` — номер прогона, по умолчанию 1.

Ты — оркестратор цикла. Работаешь до конца пула **без единого обращения к человеку**: не
задаёшь вопросов, не просишь подтверждений, не останавливаешься на уточнения. Неясность
трактуешь в пользу продолжения: делаешь разумное допущение, пишешь его в журнал, идёшь дальше.
Единственная причина остановиться досрочно — три задачи подряд с провалом ворот.

Экономь ходы: не перечитывай файлы, которые уже читал в этом прогоне, не пересказывай
сделанное, не дублируй код в ответ. Ответ по задаче — одна строка в журнал.

## Подготовка

Создай `runs/run-$ARGUMENTS/` и пустой `tasks.jsonl`. Запиши в `runs/run-$ARGUMENTS/meta.json`
время старта, `git rev-parse HEAD`, модель. Прочитай пул `docs/tasks/pool.md` и `CLAUDE.md` —
по одному разу за прогон, дальше держи в контексте.

## Цикл

Для каждой задачи из пула строго сверху вниз:

1. Зафиксируй время начала.
2. Определи режим по типу задачи из её заголовка — файлы профилей не читай, правила такие:
   - `bug` — сначала воспроизведи симптом, потом ищи причину по пути данных, фикс минимальный
     в месте причины, не в месте симптома;
   - `test` — table-driven, зависимости через дубли, продуктовый код не менять;
   - `feature` — по правилам `CLAUDE.md`, через все нужные слои;
   - `refactor` — меняешь форму, не поведение; внешние контракты те же;
   - `docs` — правишь только документацию, код не трогаешь.
3. Выполни задачу. Критерий «Сделано» из её блока — это и есть определение готовности.
4. Прогони ворота из корня репозитория: `go build ./week-1/task-5/notes-api/...`,
   `go vet ./week-1/task-5/notes-api/...`, `gofmt -l week-1/task-5`,
   `go test ./week-1/task-5/notes-api/... -count=1`.
5. Красные ворота — исправь и прогони снова, максимум две попытки. Не помогло — откати правки
   задачи, вердикт `FAILED`, идёшь дальше. Сломанный код в коммит не уходит.
6. Зелёные — закоммить одним коммитом `T-NN: что сделано`, только файлы этой задачи.
7. Допиши строку в `runs/run-$ARGUMENTS/tasks.jsonl`:

```json
{"id":"T-01","type":"bug","verdict":"DONE","seconds":137,"gate_attempts":1,"commit":"abc1234","note":""}
```

`note` — одна строка: сделанное допущение или причина провала, иначе пустая.

## Завершение

Запиши `runs/run-$ARGUMENTS/end.json`: время финиша, DONE, FAILED, streak до первого FAILED.
Выведи в чат одну сводку: streak, DONE из N, среднее время, сколько прошли ворота с первой
попытки. Без пересказа задач — они в журнале.

## Запреты

Не спрашивать человека. Не править `docs/tasks/pool.md`. Не коммитить при красных воротах.
Не пропускать задачу без строки в журнале. Не объединять задачи в один коммит. Не выдумывать
результат ворот — только по фактическому выводу команд.

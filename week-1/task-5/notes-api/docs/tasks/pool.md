# Пул задач для execution loop

Трекер — этот файл. Задачи берутся строго сверху вниз, по одной. Файл во время прогона не
правится: статус ведётся в журнале прогона.

Задачи специально мелкие и по возможности локальные — правка в одном-двух файлах, критерий
проверяется одной командой. Это сделано ради экономии ходов агента: чем меньше файлов надо
прочитать и чем однозначнее критерий, тем короче цикл на задачу.

Формат: идентификатор, тип, что сделать, критерий «сделано».

---

## T-01 · bug

`GET /notes` на пустом хранилище возвращает `null` вместо пустого массива.

**Сделано:** `MemoryRepo.List` в `internal/storage/memory.go` возвращает non-nil срез при
отсутствии заметок.

## T-02 · bug

`Service.UpdateText` не обрезает пробелы перед проверкой на пустоту, хотя `Create` обрезает,
— текст из одних пробелов проходит вместо отказа.

**Сделано:** в `internal/note/note.go` перед проверкой применяется `strings.TrimSpace`,
поведение совпадает с `Create`.

## T-03 · bug

Хендлер удаления в `internal/httpapi/handler.go` отвечает `StatusOK` вместо `StatusNoContent`.

**Сделано:** при успешном удалении отдаётся 204, тело пустое.

## T-04 · test

`Service.UpdateText` не покрыт тестами.

**Сделано:** в `internal/note/note_test.go` добавлен table-driven тест на `UpdateText`:
успешное обновление со сдвигом `UpdatedAt` при неизменном `CreatedAt`, отказ на пустом тексте,
`ErrNotFound` на неизвестном id. `go test ./week-1/task-5/notes-api/internal/note/ -count=1` зелёный.

## T-05 · test

`MemoryRepo` не покрыт тестами.

**Сделано:** файл `internal/storage/memory_test.go` покрывает `Create`, `Get`, `Update`,
`Delete`, `List` — с проверкой `ErrNotFound` через `errors.Is` и порядка выдачи `List`.

## T-06 · test

Нет теста на регрессию по T-01: пустой список должен быть `[]`, а не `null`.

**Сделано:** тест в `internal/storage/memory_test.go` проверяет, что `List` на пустом
хранилище возвращает non-nil срез нулевой длины.

## T-07 · feature

Нет эндпоинта количества заметок.

**Сделано:** `GET /notes/count` отдаёт `{"count":N}` со статусом 200, маршрут зарегистрирован
в `NewHandler`, на пустом хранилище возвращает `{"count":0}`.

## T-08 · feature

Нет проверки живости для мониторинга.

**Сделано:** `GET /healthz` отдаёт 200 и `{"status":"ok"}`, от состояния хранилища не зависит.

## T-09 · feature

Нельзя отфильтровать список по подстроке.

**Сделано:** `GET /notes?q=подстрока` фильтрует по тексту регистронезависимо; параметр читается
через `r.URL.Query().Get("q")` в существующем хендлере списка; без параметра поведение прежнее.

## T-10 · refactor

Порт и таймаут чтения заголовков зашиты числами в `cmd/notes-api/main.go`.

**Сделано:** вынесены в именованные константы уровня пакета, поведение не изменилось.

## T-11 · refactor

В `internal/httpapi/handler.go` сопоставление доменной ошибки со статусом дублируется
в нескольких хендлерах.

**Сделано:** дублирование вынесено в один вспомогательный метод, хендлеры используют его,
внешнее поведение эндпоинтов прежнее.

## T-12 · refactor

Разбор тела запроса в хендлерах создания и обновления дублируется.

**Сделано:** декодирование JSON с обработкой ошибки вынесено во вспомогательный метод,
оба хендлера используют его.

## T-13 · docs

В `README-project.md` нет описания API.

**Сделано:** появился раздел с таблицей эндпоинтов — метод, путь, назначение, коды ответов;
перечислены все маршруты из `NewHandler`.

## T-14 · docs

Не задокументированы команды запуска и проверок.

**Сделано:** в `README-project.md` есть раздел с рабочими командами запуска сервиса и полного
набора проверок.

## T-15 · docs

Список правил в `CLAUDE.md` не упоминает эндпоинты, добавленные задачами T-07, T-08, T-09.

**Сделано:** описание в `CLAUDE.md` соответствует фактическому содержимому `NewHandler`,
расхождений между документом и кодом нет.

# День 3. Testing

Двухуровневое тестирование `notes-api`, связанное в один автономный цикл командой `/qa`.

## Что в проекте нового

К сервису из Дней 1–2 добавлены веб-интерфейс и удаление, чтобы было что тестировать на
обоих уровнях:

- `internal/httpapi/web/index.html` — минимальный фронтенд: список заметок, форма создания,
  кнопка удаления. Все элементы со стабильными `data-testid` — под селекторы Playwright.
- `DELETE /notes/{id}` через все слои (repository → service → handler), плюс отдача статики
  с сервера через `embed`.

## Два уровня

**Уровень 1 — код-тесты.** Субагент `test-writer` (`.claude/agents/test-writer.md`, инструменты
`Read, Glob, Grep, Bash, Edit, Write`) сам замеряет покрытие, сам выбирает по критериям важности,
что покрывать (список файлов ему не дают), пишет table-driven тесты в стиле проекта и **доказывает
мутациями**, что они ловят регрессию: временно ломает проверяемое место, убеждается, что тест
покраснел, откатывает. Продуктовый код не трогает, чужие тесты не ослабляет.

**Уровень 2 — smoke через браузер.** Субагент `smoke-runner` (`.claude/agents/smoke-runner.md`)
прогоняет сценарии из `docs/smoke-scenarios.md` через Playwright MCP по реальному UI. Вывод о
каждом шаге делает **только из снапшота страницы** — того, что видит пользователь. У него
намеренно нет `Bash` (не поднимает сервис), `Edit` (не чинит код) и `browser_evaluate` (не может
выдернуть результат скриптом в обход интерфейса) — прямое продолжение находки Дня 2: структурный
запрет надёжнее текстового.

**Связка — команда `/qa`** (`.claude/commands/qa.md`). Субагент не может вызвать субагента,
поэтому оркестрирует команда главного агента: Уровень 1 → **ворота** (build/vet/gofmt/test, красное
= Уровень 2 не запускается) → поднять сервис → Уровень 2 → единый отчёт. Ворота оркестратор
проверяет сам, не доверяя формулировкам профилей.

## Smoke-сценарии

Пять сценариев в `docs/smoke-scenarios.md`: создание заметки, создание нескольких и проверка
списка, удаление, валидация пустого текста, пустое состояние после удаления всех.

## Как запускать

Установить Playwright MCP (один раз):

```
claude mcp add playwright npx @playwright/mcp@latest
```

Конфигурация уже лежит в `.mcp.json` (npx-вариант). Для чистой машины без node есть
`.mcp.docker.json.example` с официальным docker-образом.

Весь цикл — одной командой из каталога проекта:

```
claude
> /qa
```

Либо уровни по отдельности:

```
# Уровень 1
claude -p 'Напиши тесты на непокрытые модули' --allowedTools "Read,Glob,Grep,Bash,Edit,Write,Task"

# сначала поднять сервис, затем Уровень 2
go run ./cmd/notes-api &
claude -p 'Прогони smoke-сценарии из docs/smoke-scenarios.md' --allowedTools "Read,Glob,Grep,Write,Task"
```

## Усиление

Команда `/qa` и есть кирпич под пост-PR хук: тот же цикл (тесты + smoke + единый отчёт),
запускаемый автоматически после PR. Сценарий «задеплоил фичу — обнови smoke и прогони заново»
сводится к правке `docs/smoke-scenarios.md` и повторному `/qa`.

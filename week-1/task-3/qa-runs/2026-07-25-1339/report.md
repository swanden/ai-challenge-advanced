настоящая. Полная таблица — в `level1.md`.

**Найден баг (не чинился, профиль правит только тесты):**
`internal/storage/memory.go:79-81` — `sort.Slice` неустойчива, срез собирается обходом map,
поэтому при совпадающих `CreatedAt` порядок `List()` случайный и разный между двумя подряд
идущими вызовами (5 заметок, 200 вызовов → 5 разных порядков). Доккоммент метода обещает
детерминированную выдачу. Сквозь HTTP на этой машине не воспроизвелось (гранулярность
`SystemClock` ~1 мкс), риск реален на платформах с грубыми часами. Починка — тай-брейк по
`ID` в компараторе или `sort.SliceStable`.

## Что стоит починить (по итогам прогона)

1. **`memory.go:79-81`** — недетерминированный порядок `List()` при равных `CreatedAt`
   (найден Уровнем 1, воспроизводится тестом, требует профиля bug-fix).
2. **Профиль `smoke-runner` не может пройти S6** — в нём нет
   `mcp__playwright__browser_handle_dialog`, а UI редактирования построен на нативном
   `prompt` (`internal/httpapi/web/index.html:80`). Либо добавить тулу в профиль, либо
   заменить `prompt` на inline-редактирование с `data-testid`.
3. **Каталог артефактов Playwright MCP** — сервер пишет только внутрь своих корней
   (`notes-api/.playwright-mcp`), поэтому скриншоты приходится копировать в `qa-runs`
   постфактум. Расширить корни MCP-сервера или держать каталог прогона внутри `notes-api`.

Ни один из пунктов не блокирует текущий зелёный вердикт: №1 не воспроизводится через API на
этой платформе, №2 и №3 — ограничения оснастки, обойдённые вручную с сохранением доказательств.

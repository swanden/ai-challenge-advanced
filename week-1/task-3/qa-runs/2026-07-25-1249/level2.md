## Донабор оркестратора: PATCH на уровне API

Поскольку UI-путь S6 заблокирован, оркестратор проверил серверную часть напрямую (curl, тот же
живой инстанс). Это **не** заменяет S6 — UI-путь остаётся непроверенным, но локализует дефект:

```
POST  /notes            → {"id":"3aaebc9d173429a0","text":"Проверка PATCH",
                           "created_at":"2026-07-25T10:06:38.690355Z","updated_at":"...690355Z"}
PATCH /notes/3aaebc...  → http=200
                          {"text":"Обновлённый текст","created_at":"...690355Z",
                           "updated_at":"2026-07-25T10:06:38.703929Z"}
GET   /notes/3aaebc...  → текст «Обновлённый текст» сохранён
```

`PATCH` работает: 200, текст обновлён, `updated_at` сдвинулся, `created_at` сохранён.
**Вывод: S6 падает из-за тестируемости UI, а не из-за дефекта в Go-коде.**

## Дефекты

**D1 (blocker для S6). Редактирование через нативный `prompt()`.**
`internal/httpapi/web/index.html:80` — `const text = prompt('Новый текст заметки:', current);`.
Нативный `prompt()` не виден в accessibility tree и требует отдельного тула для диалогов, которого
у `smoke-runner` нет (`.claude/agents/smoke-runner.md` не перечисляет
`mcp__playwright__browser_handle_dialog`). Побочно: после клика сессия остаётся в modal state и не
восстанавливается навигацией — будь S6 не последним, он завалил бы и следующие сценарии.
Лечение — одно из двух:
- выдать `smoke-runner` тул `browser_handle_dialog` (минимальная правка профиля), либо
- заменить `prompt()` на inline-редактор (`input[data-testid="edit-input"]` внутри `note-item`) —
  тогда шаг проверяется снапшотом, как остальные.

**D2 (инфраструктура прогона). Каталог отчёта вне allowed roots Playwright MCP.**
Запись в `qa-runs/.../screenshots` отклонена: `File access denied: ... is outside allowed roots.
Allowed roots: .../notes-api/.playwright-mcp, .../notes-api`. Скриншоты сняты в `.playwright-mcp/`
и скопированы в `screenshots/` оркестратором вручную. Лечение — добавить в `.mcp.json`
`--output-dir` с нужным путём либо расширить allowed roots.

**D3 (сценарий). S6 в `docs/smoke-scenarios.md:45`** формулирует «в диалоге ввести новый текст», не
оговаривая, что диалог нативный — в текущем виде сценарий невыполним заявленным инструментарием.

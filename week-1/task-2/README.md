# День 2. Profiles

Профили агентного режима, целиком внутри репозитория — ничего не пишется в
домашнюю папку.

```
week-1/task-2/
├── demo-day2.sh               демо-прогон для видео
└── notes-api/
    ├── CLAUDE.md              правила проекта + раздел-селектор в конце
    └── .claude/
        ├── profiles/          режимы работы главного агента
        │   ├── bug-fix.md
        │   ├── research.md
        │   └── review.md      третий профиль (усиление)
        ├── agents/            исполнители с урезанными инструментами
        │   ├── research.md    tools: Read, Glob, Grep — без Edit/Write/Bash
        │   └── verifier.md    tools: Bash, Read, Glob, Grep — без записи
        └── skills/            процедуры, подгружаемые по необходимости
            ├── http-repro/        воспроизведение поведения живым запросом
            └── regression-test/   доказанно падающий регрессионный тест
```

**Селектор** — раздел в конце `CLAUDE.md`. Claude Code читает этот файл сам при
старте сессии, поэтому таблица «признак запроса → файл профиля» работает без
дополнительных настроек. Сам селектор работы не делает, только выбирает режим.

**Профили** — обычные markdown-файлы с методикой: порядок действий, чего не делать,
формат ответа. Claude Code про эту папку не знает и читает их по указанию селектора.

**Субагенты** — механизм Claude Code: файлы в `.claude/agents/` находятся
автоматически, а поле `tools` в шапке ограничивает инструменты. У `research` нет
`Edit`, `Write` и `Bash`, поэтому требование «не менять код» выполняется структурно,
а не по доброй воле агента.

**Скиллы** — тоже механизм Claude Code: папки в `.claude/skills/`, которые
подгружаются по необходимости, когда описание совпадает с задачей, а не висят в
контексте постоянно. Сюда вынесены две многошаговые процедуры, которым не место в
постоянно загруженном `CLAUDE.md`: как воспроизвести поведение живым запросом и как
написать регрессионный тест, доказанно падающий на старом коде. Обе используются
профилем `bug-fix`.

## Подсаженный баг

`MemoryRepo.Get` читает map без проверки второго значения и для несуществующего id
возвращает нулевую заметку с `nil` вместо `note.ErrNotFound`. Наружу это выходит как
`GET /notes/<любой-несуществующий-id>` → 200 с пустым объектом вместо 404.

Симптом виден в HTTP-слое, причина лежит двумя слоями ниже, а хендлер и сервис при
этом выглядят корректно — агенту приходится идти по всей цепочке. Ни один
существующий тест этот путь не покрывает, поэтому `go build`, `go vet` и `go test`
остаются зелёными.

## Прогон

Перед запуском обязательно зафиксировать baseline, иначе `git diff` не покажет
работу агента:

```
git add -A && git commit -m "week-1/task-2: baseline Дня 2 (профили + подсаженный баг)"
bash week-1/task-2/demo-day2.sh
```

Демо печатает пайплайн по шагам, записывать видео можно без озвучки: показывает
селектор и наборы инструментов, воспроизводит баг живым запросом при зелёных
проверках, запускает профиль `bug-fix` одним промптом, показывает диф и повторяет
запрос, затем откатывает дерево, запускает профиль `research` и доказывает, что
`git status` после него чист.

Артефакты — в `~/day2-evidence/`, намеренно вне репозитория: `git clean` на шаге
отката снёс бы их вместе с временными файлами.
